## Decisions needed from the human

- **TST-002.D1 — who writes a task's acceptance test?** The roles table gives `tests/` to QA, while §3 says every behavior change ships its test in the same commit.
  1. **(Recommended)** The implementing worker writes its own task's tests, in the same commit, under `tests/<tier>/<package>/`. QA owns the shared infrastructure (conftest, fixtures, tier audit, gate scripts, recordings) and reviews test quality.
  2. QA writes each acceptance test first, and the implementing PR waits for it.

  Option 1 needs a CLAUDE.md roles-table change, as its own PR (RUN-007.D2), before work starts.
- **ING-001.D2 — may M1 store source paths before the M2 sanitizer exists?** The hard rules forbid storing "unsanitized filenames". DESIGN §5 has `source_path` and `duplicate_paths`, and R-PIPE-2's CSV maps source → output.
  1. **(Recommended)** Store container paths (`/source/...`) only in the local ledger and in the git-ignored `results_root/reports/` CSV. Logs, console output and test output carry hashes only.
  2. Store hashes only until M2. Ingest re-walks the folder to map paths, and the CSV has no source column.
- **PIPE-001.D1 — what does `dry-run` end at in M1?** R-PIPE-2 says `proposed`, but nothing proposes an output until `name` (M5).
  1. **(Recommended)** Rows keep the last status a node set (`queued` or `skipped`). The CSV's `proposed_output` stays empty.
  2. Mark rows `proposed` now. Later nodes select by status, so they would skip these rows.
- **CFG-001.D1 — where does the config loader live?** CLAUDE.md's roles table has no owner for the package root. Proposal: `classifier/config.py`, owned by Pipeline. If you agree, it can join the same CLAUDE.md PR as TST-002.D1.
