# Milestone 4 — Status UI, read-only: `/api/status`, `/api/files`, the dashboard, `classifier report`

<!-- Rules: CLAUDE.md §1 and "Milestone gates". Written by the lead at G0. Public repo: no image names. -->

## Gate (from DESIGN.md §11)

"A dry run of the whole real folder is reviewable end to end without a terminal." · measured by `scripts/gate_4.py` (`make gate-4`), plus the human's own review at G1 (answer 6 below).

**How it is met.** The human starts `classifier dry-run` from the CLI (answer 1). From then on, every row of the ledger is reviewable in the browser at `http://127.0.0.1:8000`, or in the `classifier report` HTML, with no further terminal use. The gate script checks this mechanically. The human's look at the UI is the rest of G1.

## Scope

From DESIGN §4.8 and §11, for the read-only half of the UI:

- **R-API-1:** `classifier serve`, FastAPI, reachable on the host at `127.0.0.1:8000` only, with no auth.
- **R-API-2 (read):**
  - `GET /api/status`: run state, counts per status and category, imgs/min, VRAM, loaded model, last error;
  - `GET /api/events` (SSE);
  - `GET /api/files?status=&format=&topic=&needs_review=&page=`.
- **R-API-5:** one `ui/index.html` with vendored htmx and no build step.
  - **The dashboard:** a run banner, a topic × format count grid (safe vs adult), the latest 20 files and the errors.
  - **The review queue:** unsorted and `needs_review` files, with adult thumbnails blurred by default.
- **R-API-6:** a `runs` table plus a Postgres advisory lock (C-11). Neither exists yet.
- **R-API-7:** `classifier report [--out report.html]`, self-contained HTML built from the same JSON as the API.
- **The localhost-only proxy (RUN-001.D5),** which publishes the UI. The compose part is human-side (RUN-019).
- **M3's G1 hardening:** CLS-004.7, DB-008, CLI-009.

**Out of M4:**
- R-API-3's writes: assign, rerun, pause/resume, and a "start dry run" button (M8; answer 1).
- R-API-8: no deletion in the UI, ever.
- Captions, names and `proposed` (M5); the judge and references (M6); filing (M7).

**Privacy (ING-001.D2, P-2, DOC-007.D1):**
- No response, page or report ever carries `source_path`, `duplicate_paths` or a raw file name. They show only the sanitized name (`original_sanitized` plus the extension) and hashes.
- Thumbnails come only from `.work/thumbs/`, which ING-002 makes from the sanitized working copy.

## Privacy checklist (every task, front-loaded)

M3's list applies to every task, unchanged (`m3.md`, "Privacy checklist", items 1–10). M4 adds:

11. **No path or raw name in any response.** Every JSON model, HTML fragment, SSE event and report is built from the explicit allowlist (API-001.1). A test plants a synthetic secret in `source_path`, `duplicate_paths` and the raw stem, then asserts the secret is absent from every route's body and headers, the SSE stream and the report. It first proves the planted row is served (M3 lesson, #194, #203).
12. **Escape everything.** Every value that reaches HTML goes through the one escaping helper (API-001.D4). A planted `<script>` and a quote-breaking value in a sanitized name come out inert.
13. **Thumbnails:**
    - the route takes only a 64-hex `source_hash` that exists in the ledger, and builds the path from it, never from client input;
    - non-regular files and symlinks are refused;
    - errors are fixed text, and a miss is a plain 404;
    - adult rows are blurred by default in every view.
14. **No outbound calls from the page:** no CDN, font or analytics URL. A test scans the served HTML and the report for `http://`, `https://` and `//` references beyond the page's own origin.
15. **Logs:** uvicorn's access log is off, or logs only the method and a fixed route template. Query strings can carry category names, and they aren't logged.
